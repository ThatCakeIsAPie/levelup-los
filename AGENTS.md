# Instructions for coding agents

This repo is the unbranded Network Marketing CRM (`main`). Read `README.md`, `src/brand/README.md`, `docs/frontend-guide.md` and `docs/backend.md` before changing anything.

## Branches

- Feature work, and anything another team could use, goes to `main` first. After `main` changes, merge it into each brand branch (`levelup`, `heroes`) and push them. Pushing a brand branch deploys its demo site.
- A brand branch may change only `src/brand/**` (and `docs/design/**`). Never make a functional change directly on a brand branch; make it on `main` and merge down.

## Brand-neutral code

- Names and text come from `brand` (`brand.name`, `brand.teamName`) and `pageTitle()` in `@/lib/brand`. Never write a team or product name in code, docs or tests.
- Storage keys and IndexedDB names come from `storageKey()` and `dbName()`.
- Colours come from tokens in `src/brand/tokens.css` only; no hex or rgba values in components. A team's own colors are derived into those same tokens at runtime (`src/lib/teamColors.ts`): components never read a chosen color, and a new token that depends on the brand's main, highlight or sidebar color is added to that derivation (frontend guide, "Team appearance").
- Surfaces come from the shared components (`SectionCard`, `Card`, the `ui/` dialogs, sheets, menus): they turn into glass when a brand switches it on (`docs/frontend-guide.md`, "Glass and the background picture"). A hand-rolled panel that needs a blur adds the `glass` class.
- If you add a token or a brand field on `main`, add a value for it on every brand branch in the same piece of work, or their builds break or look wrong.
- Demo fixtures are the same on every branch: logins `@demo.test`, password `demo-local`, workspace `Demo Team`.

## Sensitive values

Feedback snapshots paint people's details as black bars. Any UI that shows one of these kinds must mark it with the helpers in `src/lib/sensitive.ts` (`<Sensitive kind="...">` from `@/components/brand` for text, `{...sensitive("...")}` on an element, input, image or avatar): `name`, `phone`, `email`, `address`, `id-number` (IBO# and LTD#), `note` (free text about a person), `message` (chat text and previews), `photo` (pictures of people, chat attachments). Mark the smallest element that holds the value. A new field, card or dialog that shows one and is not marked leaks into every snapshot.

## Database

- `supabase/seed.sql` and `supabase/tests/001_visibility_parity.test.sql` are generated by `npm run db:seed`. Never hand-edit them; regenerate and commit the result.
- A migration that has shipped is never edited. Add a new one.

## Before pushing

Run `npm run typecheck`, `npm run lint`, `npm test` and `npm run build`. Database tests (`db:test`, `test:integration`) need Docker and run in CI (`.github/workflows/ci.yml`).
